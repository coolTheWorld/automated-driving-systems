## 0. 一句话架构

```
/prediction/trajectories ─┐
/perception/obstacles ────┼─▶ 冲突计算(conflict) ─▶ 行为树选状态 ─▶ 约束合成(min) ─▶ plan()
/route/path + 剖面 ───────┘      （纯几何）        （只挑标签）     （树外，不可关）   （现有机制）
```

三条结构性红线（P7 决策四，SPEC §11）：

1. **树只选状态标签**（CRUISE/FOLLOW/YIELD，给诊断和滞回用），**不裁决约束**。
2. **约束合成在树外**：所有触发约束取最保守（停车点取 min、限速逐点取 min）。
   树上不存在「关掉某个约束」的分支 —— 结构上做不到，不靠纪律。
3. **静态障碍物准入检查原样保留**（lattice 的碰撞检查）：行为层是它的**补充**，
   不是替代。行为层全部失效时，最坏退化回 P3 的「当静态障碍物停住」。

## 1. ego 路径的时间标注

速度剖面是分段恒加速度的（`speed_profile` 的契约：段内 v² 线性），
所以段 i 的通过时间有闭式：

```
Δt_i = Δs_i / v_avg_i，  v_avg_i = (v_i + v_{i+1}) / 2
t_0 = 0（现在），t_{i+1} = t_i + Δt_i
```

- **为什么 v_avg 是精确的**：恒加速度下 Δs = v_avg·Δt 是运动学恒等式，不是近似。
- **v→0 的定义**（P7 事实 4 里的"发散要定义"）：`v_avg < 0.05 m/s` 的段取
  `Δt = +∞`（到不了）。停车点之后的所有 s 都是 +∞ —— 语义正确：
  被约束停住的车永远不会到达停车点之后，那里自然没有冲突。
- t 只在规划**内部**算，不进 `ads_msgs`（P8 前不动 ego 轨迹契约，P7 事实 4）。
- ⚠️ **两个时间轴**：标注的 t=0 在剖面起点，预测的 t=0 在「现在」（ego 所在处）。
  冲突判定一律用 `t(s) − t(ego_s)`。L1 首轮实测踩中过：全线剖面下 ego 在 s=10、
  目标在 s=60，到达时间被算成 10.8 而不是 9.0 —— 窗口整体平移错位，
  且 ego 越靠后错得越多（症状会是「越接近目标越不让行」）。
- ⚠️ 标注用**无约束剖面**（本周期约束注入前的剖面）。注入约束只会让 ego
  更晚到达，所以无约束时间是**最早到达时间** —— 用它判冲突是保守方向
  （可能多让，不会少让）。

## 2. 两类冲突分开处理（P7 事实 8 + 10：量与判分开）

**为什么必须分两类**：前车停住后预测转 STATIC，椭圆走起步律
（2σ(3s) = 13.9 m）—— 跟停逻辑若吃椭圆包络，跟车间距被一个假想的
「它可能起步冲出去」封死到 18 m 开外，跟车就不存在了。
所以：**自车道内目标用感知近边（不吃椭圆），横穿目标才用椭圆膨胀**。

### 2.1 自车道类（FOLLOW）

判定（对**感知 OBB**，不看预测）：目标中心投影到参考线得 (s_c, d_c)，

```
|d_c| ≤ corridor_half   且   s_c > s_ego
```

`corridor_half` 取车道半宽 1.75（在我的车道里的东西就是我的前车，
不论它是车、行人还是掉下来的箱子 —— STATIC 红线用例 ⑥ 由此结构性满足）。

量（近边弧长）：

```
s_near = s_c − target_length/2          （目标沿车道摆放，近似取纵向半长）
stop_at = s_near − front_offset − d_stand
```

- `front_offset = length − rear_overhang = 4.4 − 0.85 = 3.55 m`：
  轨迹点语义是**后轴**（`ads_msgs/TrajectoryPoint.msg`），停车点必须把
  车头长度让出来，否则「后轴停在近边前 4 m」= 车头贴脸 0.45 m。
- `d_stand = 4.0 m`（车头面到目标近边的站立间距）＝ 感知盲区 3 m
  （`range_min=2.2` 的近场盲区，74d12ad 写明的代价）+ 1 m 余量 ——
  **停在自己看得见的地方**。这就是 CP-P7-B ② 下界 4 m 的出处。
- 前车在动时 `s_near` 每周期前移，stop_at 跟着前移 —— **跟车 = 后退中的
  停车点**，不需要显式车距动力学（10 Hz 重规划粒度，决策二的代价已列明）。

**跟车稳态的解析**（CP-P7-A ⑤ 的判据来源）：恒速前车 v_L，剖面对停车点给出
`v(s) = √(2·a_dec·(s_stop − s))`。ego 速度收敛到 v_L 时所在位置满足
`v_L = √(2·a_dec·gap_excess)`，即稳态下

```
gap_excess = v_L² / (2·a_dec)          （v_L=3, a_dec=3 ⟹ 1.5 m）
稳态真值间距 = d_stand + gap_excess     （3 m/s 前车 ⟹ 5.5 m ∈ [4,10] ✓）
```

### 2.2 横穿类（YIELD）

对每条预测假设（`PredictedTrajectory`，t 参数化）逐点判：
点 (x_k, y_k, t_k) 投影到参考线得 (s_k, d_k)，**在走廊里**的条件

```
|d_k| ≤ corridor_half + 2·σ_cross(t_k)
```

把所有在走廊里的点聚成冲突窗 `[s_lo, s_hi] × [t_lo, t_hi]`（取包络）。
与 ego 的时间重叠判据（t_ego 来自 §1 的标注）：

```
t_lo − τ ≤ t_ego(s_hi)   且   t_ego(s_lo) ≤ t_hi + τ
```

- `τ = 1.0 s`：时间余量，吃掉预测发布延迟（新目标 ~1 s）与标注误差。
  调大 → 更早让、让得更久；调小 → 窗口贴边时抢行。
- 触发则 `stop_at = s_lo − front_offset − yield_margin`，`yield_margin = 2.0 m`
  （车头离冲突区入口的距离；比 d_stand 小 —— 冲突区不是实体，是空间）。
- **多假设按任一冲突合成**（P7 事实 11）：概率**不加权、不过滤** ——
  行人 CV 假设 0.5 概率撞上也是撞上。`existence_probability` 同样禁入。
- STATIC 假设的点在所有 t 上都是同一个 (x,y)：站在走廊里的静止目标
  ⟹ t 窗 = [0, 视界]，恒触发 —— 「横穿行人首秒只有 STATIC+增长椭圆」
  （风险表第 4 行）由此天然覆盖。
- 释放是**自然的**，不需要显式解锁：行人走出走廊后，下一周期的预测
  不再有点落在走廊里，冲突窗消失。滞回（§3）负责不抖。

### 2.3 类别裁决

一个目标只进一类：先判 FOLLOW（感知框在走廊里），否则它的预测假设进
YIELD 判定。**顺序有讲究**：走廊里的目标若同时被两类捕获，FOLLOW 的
stop_at（带 d_stand=4）比 YIELD 的（带 yield_margin=2）更保守 ——
合成取 min 时结果一样，但状态标签会抖（FOLLOW/YIELD 交替），⑨ 判据会红。

## 3. 行为树与滞回

四种节点（`behavior_tree.hpp`，全部 <150 行）：

```
Condition(fn)   tick ⟹ fn() ? Success : Failure
Action(fn)      tick ⟹ fn(); Success
Sequence(...)   逐个 tick，遇 Failure 短路返回 Failure
Fallback(...)   逐个 tick，遇 Success 短路返回 Success
```

树在代码里**显式写出**（不做 XML 加载 —— 运行时可变结构与「安全逻辑
不可关闭」相性差）：

```
Fallback(
  Sequence(Condition(有跟车冲突), Action(记 FOLLOW)),
  Sequence(Condition(有横穿冲突), Action(记 YIELD)),
  Action(记 CRUISE))
```

**滞回只在释放方向**（⑨「切换 ≤ 4 次」逼出来的设计）：

- 进入 FOLLOW/YIELD：**立即**（安全方向不等待，晚一拍 = 晚刹 0.1 s）。
- 释放回 CRUISE（或降档）：需连续 `release_cycles = 5` 个周期（0.5 s）
  无该类冲突。调大 → 让行结束后起步变慢（顶到判据 ③⑥ 的 3 s）；
  调小 → 目标在走廊边缘抖动时状态机跟着抖（⑨ 红）。
- ⚠️ 滞回作用在**状态标签**上；约束本身每周期重算重合成 ——
  释放等待期内该类冲突已消失，约束就已经没有了，车已在恢复。
  滞回防的是**标签**抖动（诊断可读性 + ⑨），不是约束抖动 ——
  约束抖动由剖面的物理限幅自然平滑（10 Hz 下 a_dec 限制斜率）。

## 4. 约束合成与注入（树外，不可关）

```
LongitudinalConstraint = { stop_at_s（可选）, caps: [{s_from, s_to, v_cap}] }
merge(约束集) = { stop_at = min(各 stop_at), caps = 并集 }
```

- **min 是安全的充分条件**：停在更早的点 ⟹ 不越过任何一个约束点。
  注入验红（CP-P7-A ③）：改成 max 或「后写覆盖」→ 两个目标时撞上更近的那个。
- 注入走**现有机制**（P7 事实 5，speed_profile 文件头「不要往这里加避障」
  的合规解法）：
  - `stop_at` → `trajectory::plan()` 的停车剖面机制（几何截断 + terminal=0），
    与 P3 绕不过去时的停车是**同一条代码路径**；
  - `caps` → `SpeedProfileParams.speed_caps`（本切片新增的可选数组）：
    `v[i] = min(曲率限速[i], cap[i])`，之后照旧前后向扫描展开成可行斜坡。
    **缺省（空）时逐字节等价于现剖面**（CP-P7-A ④ 的回归半边）。
- v1 的行为层只发 stop_at；caps 机制就位、留给 S4 实测后按需启用
  （候选：让行点前的接近限速）。机制先于用途 —— 但机制本身 L1 全覆盖。

## 5. 参数表（全部进 `planning_params.yaml` 的 behavior 段）

| 参数 | 值 | 依据 | 调大 | 调小 |
|---|---|---|---|---|
| `corridor_half_m` | 1.75 | 车道半宽 | 隔壁车道的车也触发跟停 | 走廊边缘的目标漏判 |
| `stand_off_m` (d_stand) | 4.0 | 盲区 3 + 余量 1（判据 ② 下界） | 跟得远（>10 顶判据上界） | 停进盲区，看不见自己前面 |
| `yield_margin_m` | 2.0 | 车头离冲突区入口 | 让行点远、路口通过慢 | 车头探进冲突区 |
| `time_margin_s` (τ) | 1.0 | 预测重建延迟 ~1 s | 多让（junction 全让不抢） | 窗口贴边抢行 |
| `release_cycles` | 5 | 0.5 s，⑨ 与 ③⑥ 的平衡 | 恢复慢（顶 3 s 判据） | 状态抖（⑨ 红） |
| `front_offset_m` | 3.55 | length − rear_overhang（推导量，不单独配） | — | — |

## 6. 边界（v1 明确不做的）

- **不做加速抢过**：时间窗重叠只会让行，不会「加速在 t_lo 前通过」。
  保守方向，代价是 junction 里可通过的间隙也可能让（⑦ 只要求不进冲突区）。
- **不做借道/压对向车道**（planning.md §6/§9 的 ❌ 原样保留）。
- **不做显式车距动力学**：跟车舒适性受 10 Hz 重规划粒度限制（决策二列明）。
- **横向维不参与**：约束只作用速度维，绕行候选的选择仍由 lattice 的
  静态准入 + 代价函数管。
- 预测的 `existence_probability` / 滑行状态不进任何安全判定（事实 11）。
