## 0. 术语、坐标与符号约定

| 记号 | 含义 |
|---|---|
| `map` | 全局 ENU 坐标系，**z 朝上**。本项目里它与 Gazebo 世界系重合 |
| `body` | 车体系 = `base_link`，x 前 y 左 z 上，原点在**后轴中心、地面高度** |
| `p, v, q` | 名义状态：位置（map）、速度（map）、姿态四元数（body → map） |
| `b_a, b_g` | 加速度计 / 陀螺零偏，**body 系** |
| `δθ` | 姿态误差，三维小角度向量，**body 系局部约定** |
| `f` | 加速度计读数 = **比力**（specific force），不是加速度 |
| `[v]×` | 反对称矩阵，满足 `[v]× w = v × w` |

**重力约定**：`map` 是 ENU，重力矢量 `g_vec = (0, 0, −g)`，`g = 9.80665`。

⚠️ **比力不是加速度。** 静止时加速度计读 `(0, 0, +g)`（沿 body 的 z 轴），
因为它测的是「支撑力」。世界系加速度是

```
a_world = R · f + g_vec
```

静止时两项恰好抵消为零。把 `g_vec` 的符号写反的症状是**车以 2g 下坠**，
10 s 就偏 490 m —— 这条有专门的用例 `EskfPropagation.StaticVehicleStaysPut` 守着，
且故障注入实测会让 3 条用例转红。

## 1. 为什么是「误差状态」而不是直接对状态做 KF

姿态活在流形 SO(3) 上，不是向量空间。直接把四元数的四个分量塞进 KF 状态里有三个问题：

1. 卡尔曼更新是线性组合 `x + K·y`，结果**几乎必然不再是单位四元数**。
   每步强行归一化能让程序跑下去，但归一化这个操作不在滤波器的模型里，
   于是协方差描述的不再是实际的不确定度。
2. 四元数有 4 个分量却只有 3 个自由度，协方差矩阵**必然奇异**。
3. 线性化点随姿态跑遍整个流形，一阶近似在大角度处失效。

误差状态的做法是把姿态拆成「大的名义值」和「小的误差」：

```
q = q̂ ⊗ q{δθ}
```

滤波器只对 **δθ**（三维小角度向量，李代数）做线性运算 —— 那是货真价实的向量空间。
名义值 `q̂` 单独用四元数精确积分，永远不参与线性化。每次更新后把估出来的 δθ
**注入**回 `q̂` 再清零，于是线性化点永远在原点附近。

参考：Sola,《Quaternion kinematics for the error-state Kalman filter》。

### 15 维误差状态的排布

| 索引 | 量 | 单位 | 坐标系 |
|---|---|---|---|
| 0..2 | `δp` | m | map |
| 3..5 | `δv` | m/s | map |
| 6..8 | `δθ` | rad | **body（局部）** |
| 9..11 | `δb_a` | m/s² | body |
| 12..14 | `δb_g` | rad/s | body |

⚠️ **δθ 用局部（body）约定，不是全局（map）约定。** 两者的 `F` 矩阵符号不同。
混用的症状是滤波器在**转弯时**缓慢发散而直线行驶完全正常 ——
因为 `[ω]×` 项只有转弯时才非零。

### 为什么保留完整 15 维而不退化成 2D

园区场景 roll/pitch ≈ 0 是**结果**不是**假设**。让滤波器自己估出来接近 0，
比硬约束成 0 更能暴露问题（IMU 装反了、重力方向搞错了）。
而且 roll/pitch 恰好是**地面点云唯一可观**的那几个自由度
（见 [plan.md](../../tasks/plan.md) P4-1 决策一），扔掉它们等于把 NDT 的信息丢一半。

## 2. 名义状态的推进：中值积分

前后两帧各自扣掉零偏，取平均作为区间代表：

```
a₀ = f₀ − b_a        ω₀ = ω_m0 − b_g
a₁ = f₁ − b_a        ω₁ = ω_m1 − b_g
ω_mid = ½(ω₀ + ω₁)

Δq   = q{ω_mid · dt}
q⁺   = q ⊗ Δq                              （归一化）
a_w  = ½(R · a₀ + R⁺ · a₁) + g_vec
p⁺   = p + v·dt + ½·a_w·dt²
v⁺   = v + a_w·dt
```

零偏在名义状态里**不随时间变化** —— 它的漂移只体现在误差状态的过程噪声 `Q` 里。

**为什么用中值而不是欧拉**：欧拉法只用区间起点，角度积分的截断误差是 `O(dt²)`；
中值法降到 `O(dt³)`。100 Hz、转向 0.5 rad/s 的条件下这一项本身很小，
但 P4 之后要跑几百秒的闭环，截断误差会累积，而它**不花什么代价**。

实测（`EskfPropagation.IdealImuReproducesTheCircleTrajectory`，无噪声理想 IMU，
20 s 圆周）：位置误差 < 0.05 m、速度 < 0.01 m/s、姿态 < 1e-6 rad。

**第一帧只建立时间基准，不做积分** —— 中值积分需要两帧才定义得出来。

### 时间步的两道闸

| 情形 | 处理 | 为什么 |
|---|---|---|
| `dt ≤ 0` | 抛异常 | 仿真里这通常意味着**两套仿真同时在发 `/clock`**。此时所有测量值都作废，该去查残留进程而不是改滤波器（CLAUDE.md 有专门一条） |
| `dt > max_imu_dt_s`（0.5 s） | 抛异常 | 中间丢帧了。继续积分等于用一个采样代表一整段时间，误差按 `dt²` 涨 —— 宁可让上层降级 |

## 3. 误差状态的传播

### 3.1 连续时间误差动力学

局部角误差约定下（Sola §5）：

```
δṗ   = δv
δv̇   = −R [a]× δθ − R δb_a + n_a
δθ̇   = −[ω]× δθ − δb_g + n_g
δḃ_a = n_ba
δḃ_g = n_bg
```

第二行的两项各有来历：`−R[a]×δθ` 是**姿态估偏导致比力被投到错误的方向**；
`−R δb_a` 是零偏直接污染加速度。两者都乘 `R`，因为 `a` 和 `b_a` 都在 body 系。

### 3.2 离散化

`F = I + F_c·dt` 取一阶，**只有姿态块用精确形式**：

| 块 | 值 |
|---|---|
| `F[δp, δv]` | `I·dt` |
| `F[δv, δθ]` | `−R [a_mid]× dt` |
| `F[δv, δb_a]` | `−R dt` |
| `F[δθ, δθ]` | `R{ω_mid·dt}ᵀ`（**精确**，即 `Δq` 的旋转矩阵转置） |
| `F[δθ, δb_g]` | `−I dt` |
| 零偏两块 | `I`（随机游走，一阶转移就是单位阵） |

姿态块用精确形式是因为它一样便宜，而姿态是唯一会被长时间大角速度放大的那一块。

### 3.3 过程噪声 Q

```
Q[δv,   δv  ] = σ_a²  · dt² · I
Q[δθ,   δθ  ] = σ_g²  · dt² · I
Q[δb_a, δb_a] = σ_ba² · dt  · I
Q[δb_g, δb_g] = σ_bg² · dt  · I
```

白噪声项按 `σ²dt²` 进（速度/姿态是噪声的**积分**），零偏随机游走按 `σ²dt` 进
（它本身就是布朗运动）。

⚠️ **这四项都不能填 0。** 全 0 的 `Q` 意味着滤波器认为自己的预测毫无误差，
协方差会单调收缩到 0，卡尔曼增益随之趋于 0 —— 之后**任何观测都被无视**，
位置一路漂走而滤波器始终报告「很准」。
故障注入实测：把 `Q` 整块丢掉，4 条用例转红。

**闭式解可对账**：只有陀螺白噪声时，姿态方差严格正比于时间，

```
σ_θ(t) = σ_g · √(dt · t)
```

`EskfCovariance.AttitudeUncertaintyGrowsAsSqrtOfTimeWithoutObservations` 就是验这个，
判据是 100 s 时与闭式解相差 < 2%，且 25 s → 100 s 的比值 = 2.00 ± 0.02。

⚠️ **位置那一项不是 √t**。位置是速度误差的积分，增长是 `t^1.5`。判据别写错。

## 4. 观测更新

### 4.1 三路观测与各自的雅可比

| 观测 | 模型 `h(x)` | `∂h/∂δv` | `∂h/∂δθ` | 典型 σ |
|---|---|---|---|---|
| GNSS 定位（3 维） | `p` | — | — | 2 m 水平 / 4 m 垂直 |
| GNSS 测速（3 维） | `v` | `I` | **0** | 0.05 m/s 水平 |
| 轮速（1 维） | `(Rᵀv)_x` | `R̂ᵀ` 第 0 行 | `[v̂_body]×` 第 0 行 | 0.05 m/s |

轮速的雅可比推导（`R = R̂(I + [δθ]×)`）：

```
v_body = (I − [δθ]×) R̂ᵀ (v̂ + δv)
       ≈ v̂_body + R̂ᵀ δv − [δθ]× v̂_body
       = v̂_body + R̂ᵀ δv + [v̂_body]× δθ
```

### 4.2 ⚠️ GNSS 测速是一路**独立**观测，不要以为它冗余

定位解算的是**伪距**（米级），测速解算的是**载波多普勒** —— 后者精度高两个数量级
（本项目 0.05 m/s vs 2 m）。不用它等于白扔掉最精确的那一路。

它对**位置**精度的贡献是间接但巨大的：速度估得准 → 两次定位之间的推算更准 →
滤波器能把更长时间窗内的定位观测平均掉。

**实测（2026-08-07，八字形合成轨迹 400 s，5 个种子）**：

| 观测组合 | 位置 RMS | 末姿态误差 |
|---|---|---|
| 定位 + 轮速 | 0.425 m | 0.0205 rad |
| **定位 + 轮速 + 测速** | **0.211 m** | **0.00049 rad** |

**少接一路观测不会报错，只会让精度停在一个看似合理的数上。**
`EskfFusion.GnssVelocityObservationEarnsItsPlace` 是这条的消融用例。

### 4.3 ⚠️ 轮速的姿态雅可比在无侧滑时**恒为零**

`[v_body]×` 的第 0 行是 `(0, −v_z, v_y)`。车不侧滑时 `v_body = (速度, 0, 0)`，
于是这一行**精确为零** —— 纵向速度观测对姿态没有一阶耦合。

实测（无 GNSS、只靠轮速辅助的 120 s 推算）：**删掉这一项漂移反而更小**，
62.0 m → 30.6 m，因为保留它等于把速度噪声喂进航向。

仍然保留它，理由是：① 数学上是对的；② 真车与 Gazebo 在大横向加速度下确实有侧滑，
那时 `v_body.y ≠ 0`，这一项就有了物理内容。

**但不要指望有测试守着它** —— 一个恒为零的项没有可观测的行为差异。
（这里曾经写过「漏掉它会让转弯时航向慢慢偏」，那是**错的**，已被注入实验推翻。）

### 4.4 协方差更新用 Joseph 形式

```
P⁺ = (I − KH) P (I − KH)ᵀ + K R Kᵀ
```

而不是更常见的简写 `P⁺ = (I − KH) P`。两者在精确算术下等价，但简写形式只有在
`K` 恰好是最优增益时才成立，且结果不保证对称。Joseph 形式的右边是两个 `XPXᵀ` 型的和，
**结构上就是对称半正定的**，代价是多一次 15×15 乘法。

⚠️ **诚实说明**：本实现在 Joseph 之后还紧跟一行强制对称化
`P ← ½(P + Pᵀ)`，而那一行把 Joseph 的对称性收益盖住了。
故障注入实测：**把 Joseph 换成简写形式，没有任何用例变红**。
保留 Joseph 是因为它是教科书正确形式且几乎不花钱，
**但不要声称测试覆盖了这个选择**。

## 5. 注入与重置

```
p  += δp      v += δv      b_a += δb_a      b_g += δb_g
q   = q ⊗ q{δθ}                             ← **右乘，不是相加**
```

姿态必须右乘 —— 它活在流形上。
故障注入实测：写成 `q.coeffs().head<3>() += 0.5·δθ`，3 条用例转红。

**重置**这一步最容易被漏掉，而漏掉之后滤波器看起来完全正常：
误差被注入名义状态后必须清零，否则同一份修正会在下次更新里被重复计入 ——
症状是**缓慢发散**而不是立刻出错。本实现里误差是局部变量，天然清零了，
所以真正需要显式做的是协方差那一半：

线性化点从 `q̂` 挪到了 `q̂ ⊗ q{δθ}`，δθ 的协方差要跟着做坐标变换，
雅可比是 `G_θ = I − ½[δθ]×`（Sola eq. 285），`P ← G P Gᵀ`。

⚠️ **诚实说明**：故障注入实测，**省掉这一项没有任何用例变红**。
这与代码注释里的预判一致（「省掉之后没有任何现象能提示你」）。
保留它是因为省掉会让协方差系统性地略微**偏乐观**，
而「偏乐观」正是滤波器最难被发现的那类错误 —— 但它目前**无测试守护**。

## 6. 零偏可观性 —— 本模块最反直觉的一节

**零偏能不能被估出来，取决于车怎么开，不取决于滤波器写得好不好。**

实测（2026-08-07，单独注入某一个零偏分量，跑 GNSS + 轮速融合）：

| 轨迹 | 时长 | 加速度计 x/y/z 相对误差 | 陀螺 x/y/z 相对误差 |
|---|---|---|---|
| 匀速圆周 | 200 s | 0.073 / 0.631 / 0.210 | **1.466** / 0.836 / 0.191 |
| 匀速圆周 | 1000 s | **1.659** / 0.856 / 0.225 | **2.070** / 0.772 / 0.055 |
| 八字形 + 速度调制 | 200 s | 0.056 / 0.428 / 0.016 | 0.077 / 0.101 / 0.066 |
| 八字形 + 速度调制 | 1000 s | 0.108 / 0.049 / 0.023 | 0.005 / 0.042 / 0.169 |

**匀速圆周上时间跑得越久反而越差。** 原因：车以恒定 ω 偏航，body 系的常值零偏
在世界系里**匀速旋转**，一个周期内积分恰好抵消 —— 它产生的是幅值 `|b|/ω²` 的
**有界振荡**而不是漂移，于是几乎不可观。

八字形打破了这个对称（ψ̇ 变号），速度调制又补上了纵向激励 ——
这正是真实 INS 的对准流程要求「既转弯又加减速」的原因。

⚠️ **所以看到「零偏估不出来」时，第一件事是确认那条轨迹上它到底可不可观，
而不是去调 `Q`。** 仓库里保留了 `EskfDiagnostics.DISABLED_BiasObservabilityOnAConstantRateCircle`
这个默认不跑的对照用例，就是为了让下一个人能一分钟内自己量一遍。

## 8. 参数与调大调小的后果

参数在 `EskfParams`，量级与 `config/vehicle_params.yaml` 的 `noise` 段同源。

| 参数 | 本项目取值 | 调大 | 调小 |
|---|---|---|---|
| `gyro_noise_rad_s` | 8.7e-4 | 姿态随机游走快，更依赖绝对观测 | 滤波器过度相信陀螺，转弯时航向跟不上 |
| `accel_noise_mps2` | 1.0e-2 | 速度不确定度涨得快 | 同上，且零偏更难被估出来 |
| `gyro_bias_rw_rad_s` | 4.8e-5 | 认为零偏变化快，跟得快也更容易被噪声带偏 | 零偏估计变"僵"，真实漂移跟不上 |
| `accel_bias_rw_mps2` | 1.0e-4 | 同上 | 同上 |
| `init_*_std_*` | 见代码 | 初期更信观测 | **填 0 = 增益恒为 0，该状态永远不被修正** |
| `max_imu_dt_s` | 0.5 | 容忍更大的丢帧，但误差按 dt² 涨 | 抖动一下就抛异常 |

⚠️ **GNSS 的 σ 不是可调参数，是传感器规格。**
不要因为「定位误差超标」就把 `config/vehicle_params.yaml` 里的 GNSS 噪声调小 ——
那是把判据改成能通过的样子。单点定位下 ESKF 到不了 SPEC §1 的 0.3 m，
这正是必须做 NDT 的理由（[plan.md](../../tasks/plan.md) P4-1 决策一）。
