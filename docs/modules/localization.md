## 0. 术语、坐标与符号约定

| 记号 | 含义 |
|---|---|
| `map` | 全局 ENU 坐标系，**z 朝上**。本项目里它与 Gazebo 世界系重合 |
| `body` | 车体系 = `base_link`，x 前 y 左 z 上，原点在**后轴中心、地面高度** |
| `p, v, q` | 名义状态：位置（map）、速度（map）、姿态四元数（body → map） |
| `b_a, b_g` | 加速度计 / 陀螺零偏，**body 系** |
| `δθ` | 姿态误差，三维小角度向量，**body 系局部约定** |
| `f` | 加速度计读数 = **比力**（specific force），不是加速度 |
| `[v]×` | 反对称矩阵，满足 `[v]× w = v × w` |

**重力约定**：`map` 是 ENU，重力矢量 `g_vec = (0, 0, −g)`，`g = 9.80665`。

⚠️ **比力不是加速度。** 静止时加速度计读 `(0, 0, +g)`（沿 body 的 z 轴），
因为它测的是「支撑力」。世界系加速度是

```
a_world = R · f + g_vec
```

静止时两项恰好抵消为零。把 `g_vec` 的符号写反的症状是**车以 2g 下坠**，
10 s 就偏 490 m —— 这条有专门的用例 `EskfPropagation.StaticVehicleStaysPut` 守着，
且故障注入实测会让 3 条用例转红。

## 1. 为什么是「误差状态」而不是直接对状态做 KF

姿态活在流形 SO(3) 上，不是向量空间。直接把四元数的四个分量塞进 KF 状态里有三个问题：

1. 卡尔曼更新是线性组合 `x + K·y`，结果**几乎必然不再是单位四元数**。
   每步强行归一化能让程序跑下去，但归一化这个操作不在滤波器的模型里，
   于是协方差描述的不再是实际的不确定度。
2. 四元数有 4 个分量却只有 3 个自由度，协方差矩阵**必然奇异**。
3. 线性化点随姿态跑遍整个流形，一阶近似在大角度处失效。

误差状态的做法是把姿态拆成「大的名义值」和「小的误差」：

```
q = q̂ ⊗ q{δθ}
```

滤波器只对 **δθ**（三维小角度向量，李代数）做线性运算 —— 那是货真价实的向量空间。
名义值 `q̂` 单独用四元数精确积分，永远不参与线性化。每次更新后把估出来的 δθ
**注入**回 `q̂` 再清零，于是线性化点永远在原点附近。

参考：Sola,《Quaternion kinematics for the error-state Kalman filter》。

### 15 维误差状态的排布

| 索引 | 量 | 单位 | 坐标系 |
|---|---|---|---|
| 0..2 | `δp` | m | map |
| 3..5 | `δv` | m/s | map |
| 6..8 | `δθ` | rad | **body（局部）** |
| 9..11 | `δb_a` | m/s² | body |
| 12..14 | `δb_g` | rad/s | body |

⚠️ **δθ 用局部（body）约定，不是全局（map）约定。** 两者的 `F` 矩阵符号不同。
混用的症状是滤波器在**转弯时**缓慢发散而直线行驶完全正常 ——
因为 `[ω]×` 项只有转弯时才非零。

### 为什么保留完整 15 维而不退化成 2D

园区场景 roll/pitch ≈ 0 是**结果**不是**假设**。让滤波器自己估出来接近 0，
比硬约束成 0 更能暴露问题（IMU 装反了、重力方向搞错了）。
而且 roll/pitch 恰好是**地面点云唯一可观**的那几个自由度
（见 [plan.md](../../tasks/plan.md) P4-1 决策一），扔掉它们等于把 NDT 的信息丢一半。

## 2. 名义状态的推进：中值积分

前后两帧各自扣掉零偏，取平均作为区间代表：

```
a₀ = f₀ − b_a        ω₀ = ω_m0 − b_g
a₁ = f₁ − b_a        ω₁ = ω_m1 − b_g
ω_mid = ½(ω₀ + ω₁)

Δq   = q{ω_mid · dt}
q⁺   = q ⊗ Δq                              （归一化）
a_w  = ½(R · a₀ + R⁺ · a₁) + g_vec
p⁺   = p + v·dt + ½·a_w·dt²
v⁺   = v + a_w·dt
```

零偏在名义状态里**不随时间变化** —— 它的漂移只体现在误差状态的过程噪声 `Q` 里。

**为什么用中值而不是欧拉**：欧拉法只用区间起点，角度积分的截断误差是 `O(dt²)`；
中值法降到 `O(dt³)`。100 Hz、转向 0.5 rad/s 的条件下这一项本身很小，
但 P4 之后要跑几百秒的闭环，截断误差会累积，而它**不花什么代价**。

实测（`EskfPropagation.IdealImuReproducesTheCircleTrajectory`，无噪声理想 IMU，
20 s 圆周）：位置误差 < 0.05 m、速度 < 0.01 m/s、姿态 < 1e-6 rad。

**第一帧只建立时间基准，不做积分** —— 中值积分需要两帧才定义得出来。

### 时间步的两道闸

| 情形 | 处理 | 为什么 |
|---|---|---|
| `dt ≤ 0` | 抛异常 | 仿真里这通常意味着**两套仿真同时在发 `/clock`**。此时所有测量值都作废，该去查残留进程而不是改滤波器（CLAUDE.md 有专门一条） |
| `dt > max_imu_dt_s`（0.5 s） | 抛异常 | 中间丢帧了。继续积分等于用一个采样代表一整段时间，误差按 `dt²` 涨 —— 宁可让上层降级 |

## 3. 误差状态的传播

### 3.1 连续时间误差动力学

局部角误差约定下（Sola §5）：

```
δṗ   = δv
δv̇   = −R [a]× δθ − R δb_a + n_a
δθ̇   = −[ω]× δθ − δb_g + n_g
δḃ_a = n_ba
δḃ_g = n_bg
```

第二行的两项各有来历：`−R[a]×δθ` 是**姿态估偏导致比力被投到错误的方向**；
`−R δb_a` 是零偏直接污染加速度。两者都乘 `R`，因为 `a` 和 `b_a` 都在 body 系。

### 3.2 离散化

`F = I + F_c·dt` 取一阶，**只有姿态块用精确形式**：

| 块 | 值 |
|---|---|
| `F[δp, δv]` | `I·dt` |
| `F[δv, δθ]` | `−R [a_mid]× dt` |
| `F[δv, δb_a]` | `−R dt` |
| `F[δθ, δθ]` | `R{ω_mid·dt}ᵀ`（**精确**，即 `Δq` 的旋转矩阵转置） |
| `F[δθ, δb_g]` | `−I dt` |
| 零偏两块 | `I`（随机游走，一阶转移就是单位阵） |

姿态块用精确形式是因为它一样便宜，而姿态是唯一会被长时间大角速度放大的那一块。

### 3.3 过程噪声 Q

```
Q[δv,   δv  ] = σ_a²  · dt² · I
Q[δθ,   δθ  ] = σ_g²  · dt² · I
Q[δb_a, δb_a] = σ_ba² · dt  · I
Q[δb_g, δb_g] = σ_bg² · dt  · I
```

白噪声项按 `σ²dt²` 进（速度/姿态是噪声的**积分**），零偏随机游走按 `σ²dt` 进
（它本身就是布朗运动）。

⚠️ **这四项都不能填 0。** 全 0 的 `Q` 意味着滤波器认为自己的预测毫无误差，
协方差会单调收缩到 0，卡尔曼增益随之趋于 0 —— 之后**任何观测都被无视**，
位置一路漂走而滤波器始终报告「很准」。
故障注入实测：把 `Q` 整块丢掉，4 条用例转红。

**闭式解可对账**：只有陀螺白噪声时，姿态方差严格正比于时间，

```
σ_θ(t) = σ_g · √(dt · t)
```

`EskfCovariance.AttitudeUncertaintyGrowsAsSqrtOfTimeWithoutObservations` 就是验这个，
判据是 100 s 时与闭式解相差 < 2%，且 25 s → 100 s 的比值 = 2.00 ± 0.02。

⚠️ **位置那一项不是 √t**。位置是速度误差的积分，增长是 `t^1.5`。判据别写错。

## 4. 观测更新

### 4.1 三路观测与各自的雅可比

| 观测 | 模型 `h(x)` | `∂h/∂δv` | `∂h/∂δθ` | 典型 σ |
|---|---|---|---|---|
| GNSS 定位（3 维） | `p` | — | — | 2 m 水平 / 4 m 垂直 |
| GNSS 测速（3 维） | `v` | `I` | **0** | 0.05 m/s 水平 |
| 轮速（1 维） | `(Rᵀv)_x` | `R̂ᵀ` 第 0 行 | `[v̂_body]×` 第 0 行 | 0.05 m/s |

轮速的雅可比推导（`R = R̂(I + [δθ]×)`）：

```
v_body = (I − [δθ]×) R̂ᵀ (v̂ + δv)
       ≈ v̂_body + R̂ᵀ δv − [δθ]× v̂_body
       = v̂_body + R̂ᵀ δv + [v̂_body]× δθ
```

### 4.2 ⚠️ GNSS 测速是一路**独立**观测，不要以为它冗余

定位解算的是**伪距**（米级），测速解算的是**载波多普勒** —— 后者精度高两个数量级
（本项目 0.05 m/s vs 2 m）。不用它等于白扔掉最精确的那一路。

它对**位置**精度的贡献是间接但巨大的：速度估得准 → 两次定位之间的推算更准 →
滤波器能把更长时间窗内的定位观测平均掉。

**实测（2026-08-07，八字形合成轨迹 400 s，5 个种子）**：

| 观测组合 | 位置 RMS | 末姿态误差 |
|---|---|---|
| 定位 + 轮速 | 0.425 m | 0.0205 rad |
| **定位 + 轮速 + 测速** | **0.211 m** | **0.00049 rad** |

**少接一路观测不会报错，只会让精度停在一个看似合理的数上。**
`EskfFusion.GnssVelocityObservationEarnsItsPlace` 是这条的消融用例。

### 4.3 ⚠️ 轮速的姿态雅可比在无侧滑时**恒为零**

`[v_body]×` 的第 0 行是 `(0, −v_z, v_y)`。车不侧滑时 `v_body = (速度, 0, 0)`，
于是这一行**精确为零** —— 纵向速度观测对姿态没有一阶耦合。

实测（无 GNSS、只靠轮速辅助的 120 s 推算）：**删掉这一项漂移反而更小**，
62.0 m → 30.6 m，因为保留它等于把速度噪声喂进航向。

仍然保留它，理由是：① 数学上是对的；② 真车与 Gazebo 在大横向加速度下确实有侧滑，
那时 `v_body.y ≠ 0`，这一项就有了物理内容。

**但不要指望有测试守着它** —— 一个恒为零的项没有可观测的行为差异。
（这里曾经写过「漏掉它会让转弯时航向慢慢偏」，那是**错的**，已被注入实验推翻。）

### 4.4 协方差更新用 Joseph 形式

```
P⁺ = (I − KH) P (I − KH)ᵀ + K R Kᵀ
```

而不是更常见的简写 `P⁺ = (I − KH) P`。两者在精确算术下等价，但简写形式只有在
`K` 恰好是最优增益时才成立，且结果不保证对称。Joseph 形式的右边是两个 `XPXᵀ` 型的和，
**结构上就是对称半正定的**，代价是多一次 15×15 乘法。

⚠️ **诚实说明**：本实现在 Joseph 之后还紧跟一行强制对称化
`P ← ½(P + Pᵀ)`，而那一行把 Joseph 的对称性收益盖住了。
故障注入实测：**把 Joseph 换成简写形式，没有任何用例变红**。
保留 Joseph 是因为它是教科书正确形式且几乎不花钱，
**但不要声称测试覆盖了这个选择**。

## 5. 注入与重置

```
p  += δp      v += δv      b_a += δb_a      b_g += δb_g
q   = q ⊗ q{δθ}                             ← **右乘，不是相加**
```

姿态必须右乘 —— 它活在流形上。
故障注入实测：写成 `q.coeffs().head<3>() += 0.5·δθ`，3 条用例转红。

**重置**这一步最容易被漏掉，而漏掉之后滤波器看起来完全正常：
误差被注入名义状态后必须清零，否则同一份修正会在下次更新里被重复计入 ——
症状是**缓慢发散**而不是立刻出错。本实现里误差是局部变量，天然清零了，
所以真正需要显式做的是协方差那一半：

线性化点从 `q̂` 挪到了 `q̂ ⊗ q{δθ}`，δθ 的协方差要跟着做坐标变换，
雅可比是 `G_θ = I − ½[δθ]×`（Sola eq. 285），`P ← G P Gᵀ`。

⚠️ **诚实说明**：故障注入实测，**省掉这一项没有任何用例变红**。
这与代码注释里的预判一致（「省掉之后没有任何现象能提示你」）。
保留它是因为省掉会让协方差系统性地略微**偏乐观**，
而「偏乐观」正是滤波器最难被发现的那类错误 —— 但它目前**无测试守护**。

## 6. 零偏可观性 —— 本模块最反直觉的一节

**零偏能不能被估出来，取决于车怎么开，不取决于滤波器写得好不好。**

实测（2026-08-07，单独注入某一个零偏分量，跑 GNSS + 轮速融合）：

| 轨迹 | 时长 | 加速度计 x/y/z 相对误差 | 陀螺 x/y/z 相对误差 |
|---|---|---|---|
| 匀速圆周 | 200 s | 0.073 / 0.631 / 0.210 | **1.466** / 0.836 / 0.191 |
| 匀速圆周 | 1000 s | **1.659** / 0.856 / 0.225 | **2.070** / 0.772 / 0.055 |
| 八字形 + 速度调制 | 200 s | 0.056 / 0.428 / 0.016 | 0.077 / 0.101 / 0.066 |
| 八字形 + 速度调制 | 1000 s | 0.108 / 0.049 / 0.023 | 0.005 / 0.042 / 0.169 |

**匀速圆周上时间跑得越久反而越差。** 原因：车以恒定 ω 偏航，body 系的常值零偏
在世界系里**匀速旋转**，一个周期内积分恰好抵消 —— 它产生的是幅值 `|b|/ω²` 的
**有界振荡**而不是漂移，于是几乎不可观。

八字形打破了这个对称（ψ̇ 变号），速度调制又补上了纵向激励 ——
这正是真实 INS 的对准流程要求「既转弯又加减速」的原因。

⚠️ **所以看到「零偏估不出来」时，第一件事是确认那条轨迹上它到底可不可观，
而不是去调 `Q`。** 仓库里保留了 `EskfDiagnostics.DISABLED_BiasObservabilityOnAConstantRateCircle`
这个默认不跑的对照用例，就是为了让下一个人能一分钟内自己量一遍。

## 8. 参数与调大调小的后果

参数在 `EskfParams`，量级与 `config/vehicle_params.yaml` 的 `noise` 段同源。

| 参数 | 本项目取值 | 调大 | 调小 |
|---|---|---|---|
| `gyro_noise_rad_s` | 8.7e-4 | 姿态随机游走快，更依赖绝对观测 | 滤波器过度相信陀螺，转弯时航向跟不上 |
| `accel_noise_mps2` | 1.0e-2 | 速度不确定度涨得快 | 同上，且零偏更难被估出来 |
| `gyro_bias_rw_rad_s` | 4.8e-5 | 认为零偏变化快，跟得快也更容易被噪声带偏 | 零偏估计变"僵"，真实漂移跟不上 |
| `accel_bias_rw_mps2` | 1.0e-4 | 同上 | 同上 |
| `init_*_std_*` | 见代码 | 初期更信观测 | **填 0 = 增益恒为 0，该状态永远不被修正** |
| `max_imu_dt_s` | 0.5 | 容忍更大的丢帧，但误差按 dt² 涨 | 抖动一下就抛异常 |

⚠️ **GNSS 的 σ 不是可调参数，是传感器规格。**
不要因为「定位误差超标」就把 `config/vehicle_params.yaml` 里的 GNSS 噪声调小 ——
那是把判据改成能通过的样子。单点定位下 ESKF 到不了 SPEC §1 的 0.3 m，
这正是必须做 NDT 的理由（[plan.md](../../tasks/plan.md) P4-1 决策一）。

## 9. NDT 配准（S3）

### 9.1 体素高斯地图

把先验点云切成 2 m 体素，每格里的点拟合一个三维高斯。配准因此从「点找最近点」
变成「代进高斯求似然」，代价函数处处可微。

两个必须正面处理的退化情形：

| 情形 | 实测（真实 `campus_cloud.pcd`） | 处理 |
|---|---|---|
| 稀疏体素（点数 < 4 时样本协方差自由度 ≤ 0） | 丢弃 369 个 | 门限 6 个点，**并报出丢弃数** |
| **共面体素**（协方差 rank 2，求逆会炸） | **3660/3985 = 91.8%** | 特征值下限 `λ_max·0.01` |

⚠️ **91.8% 这个数字值得单独记住**：路面是平面，**建筑墙面也是平面**，
单个体素几乎都是平的。**可观性来自体素之间法向的多样性，不是单个体素的三维性。**

### 9.2 代价函数与导数

```
e = x − μ          q = eᵀΣ⁻¹e          s = −exp(−q/2)      （越小越好）
∂x/∂δt = I         ∂x/∂δθ = −R̂[p]×
g = Σ w·JᵀΣ⁻¹e     H ≈ Σ w·JᵀΣ⁻¹J      （w = exp(−q/2)）
```

H 用 **Gauss-Newton 近似**（丢掉完整 Hessian 里那个负半定项）有两个理由，
第二个才是关键：① H 结构上半正定，`−H⁻¹g` 一定是下降方向；
② **`Σ w JᵀΣ⁻¹J` 恰好就是 Fisher 信息阵**，也就是要输出给 ESKF 的协方差的正确对象。

解析梯度有专门的用例与**数值微分逐项对账**。符号写反的症状是「配准朝反方向跑
然后卡住」，看起来像收敛域太小 —— 会把人引到调参数上去。

### 9.3 ⚠️ 必须求和邻域体素，不能只用「包含该点的那一个」

只用包含点的那一个体素时，点跨过边界的瞬间**换了一个高斯**，代价函数是**锯齿状**的。

2026-08-10 实测（初值偏 0.94 m + 3°）：牛顿步的**方向完全正确**
（`(−0.029, +0.016)` vs 需要的 `(−0.8, +0.5)` 方向一致），但代价函数的改善窗口
只有步长的 **1/500**，线搜索折半十次都跨不进去 —— 配准一步不动而且报 converged。

改成 3×3×3 邻域求和之后：**27 次迭代，位置残差 0.0024 m、姿态残差 0.0001 rad**。

邻域求和在数学上也更正确：地图本来就是一个**高斯混合**，点在该处的似然是所有
分量密度之和。而且它连续 —— 刚进入邻域的体素距离 ≥ 一个体素，权重是指数小的。

### 9.4 ⚠️ 退化检测看**法向散布**，不看信息阵条件数

这是走过一次弯路之后的结论，值得完整记下来。

P4-1 决策一的原话：约束来自表面法向，一个平面只约束沿它法向的那一个自由度。
所以判据是「匹配上的体素法向是否平行」：

```
N = Σ w·n nᵀ        （n = 体素协方差**最小**特征值对应的特征向量）
normal_diversity = λ_min(N) / λ_max(N)      取值 0 … 1/3
```

**第一版用了信息阵 H 的条件数，那是错的。** 实测对比：

| 场景 | 法向散布 | 信息阵条件数 | H⁻¹ 报出的 σ_x |
|---|---|---|---|
| 结构齐全的园区地图 | **0.3095** | 3.17e3 | 4.4 mm |
| 纯地面 | **1.05e-05** | 9.25e3 | **8.7 mm** |
| 走廊（两面平行墙 + 地面） | **1.14e-04** | — | — |

纯地面上 H 报出 σ_x = 8.7 mm —— 也就是「**在一个无特征平面上把 x 定到了 9 毫米**」，
而条件数只比结构齐全的情形差 3 倍。原因是**体素离散化伪造了面内信息**：
每格高斯的均值落在该格质心，整张地图在面内构成一个 2 m 点阵，扫描平移会撞上纹波。
那个信息相对**离散化后的地图**是真的，相对**物理世界**是假的 ——
NDT 会老老实实收敛到纹波的某个谷底，给出一个看起来很准的错位姿。

换成法向散布之后两者差 **6 个数量级**，判据 1e-3 落在中间，两侧余量各有 100–300 倍。

⚠️ **法向必须取最小特征值方向。** 取成最大方向时纯地面那条用例**照样通过**
（两种取法在地面上碰巧同判定），只有**走廊**能分开：正确取法给 1.14e-4（退化），
错误取法给 0.4441（看着很健康）。走廊是自动驾驶里最经典的 NDT 失效场景
（隧道、两侧连续建筑、货架巷道），这条用例是故障注入逼出来的。

### 9.5 输出协方差**尚未标定**

`covariance = covariance_scale · H⁻¹`，而 `covariance_scale` 现在是 **1.0，未标定**。

本实现的得分函数不是严格归一化的对数似然，所以 `H⁻¹` 只与真实协方差**成正比**。
真正的比例要在 S4 拿实测误差与它对账之后才定得下来。
**一个没标定的协方差喂进 ESKF 的后果是权重错，而那不会报错。**

## 10. `localization_node`（S4）与 CP-P4-B

### 10.1 数据流与 `map → odom`

```
/imu (100 Hz) ─────┐
/gnss (10 Hz) ─────┤
/odom (轮速) ──────┼──▶ localization_node ──▶ TF map→odom（**主产出**）
/lidar/points ─────┘                      ├──▶ /localization/pose
                                          └──▶ /localization/diagnostics
```

发 `map→odom` 而不是 `map→base_link`：`odom→base_link` 由轮速里程计给（高频、平滑、
但漂移），定位只负责那段低频修正量，于是**下游拿到的位姿始终连续**。
直接发 `map→base_link` 会让 TF 树上 `base_link` 有两个父节点，tf2 直接报错。

`localization:=true` 时，仿真侧那条来自 spawn 位姿的静态 TF **必须同时关掉**。

⚠️ **这条约束的可怕之处不是"违反了会出事"，而是"违反了可能什么都看不出来"。**
L3-G 的故障注入实测（2026-08-10）：在正常闭环上再挂一个静态 `map→odom`，
末段位置误差只从 **0.012 m 变成 0.043 m**，末态仍是 `NDT_AIDED`，
所有数值判据照样绿。

原因是 tf2 的行为**取决于两个发布者的启动顺序**：某个 frame 第一次被写入时，
tf2 就定死它用静态缓存还是时间缓存。本次是静态先到（`static_transform_publisher`
在 t=0 就发，而定位要等 GNSS 初始化完），于是那一段落进静态缓存，
随后的动态变换把它覆盖掉 —— 动态赢了，看起来一切正常。顺序反过来则不是这个结果。

**一个结果取决于启动顺序的系统，不能靠观察它这一次的输出来验收。**
所以 `test_closed_loop_localization.py` 的断言 ③ 是**机械地查 `/tf_static` 上
有没有 `map→odom`**，而不是看误差有没有变大。

### 10.2 ⚠️ 五个根因 —— 每一个单独都会让定位崩掉

CP-P4-B 前后跑了十几轮才收敛。**这五条没有一条能靠读代码看出来**，
全部是实测挖出来的；它们也解释了为什么中途有几轮"同一份配置结果差 1000 倍"。

#### (1) 单次 GNSS 初始化 → 锁到错误的局部极小

用单次 GNSS 定位当初值（σ=2 m）时，结果是**双峰**的：同一份配置跑五轮，
横向误差在 0.0664 m 和 78 m 之间跳，差别只是开机那一枪的运气。

初值偏 1.6 m 时落在 NDT 收敛域之外，NDT 于是收敛到一个**错误的局部极小** ——
而它法向散布正常、inlier 正常、协方差很紧，**一个警告都不报**。

修法：GNSS 位置噪声是**白噪声**（SDF 里只有 `stddev`、无 bias 项），
平均 30 次把 σ 从 2 m 降到 0.37 m。车启动后本来要静止约 30 s 才发目标点，
这 3 s 不花任何代价。

#### (2) ⚠️ NDT 慢过雷达周期 → 执行器积压 → 用越来越旧的点云配准

**这是最隐蔽的一个，也是中途所有「失锁」现象的真正根因。**

NDT 一旦超过 100 ms，单线程执行器排队，处理的点云越来越旧 —— 而 NDT 会
**老老实实把那帧旧扫描配准好**，返回它**拍摄时刻**的位姿。于是：

| 现场看到的 | 实际发生的 |
|---|---|
| 全程 `NDT_AIDED` | NDT 每帧都"成功" |
| 横向误差只有 3 cm | 因为误差**纯粹是纵向**的 |
| 零报警 | 没有任何判据在看时延 |
| 车冲过目标 24 m | 控制器按滞后的估计判断"还没到" |

铁证是 `/localization/pose` 的发布率掉一半（54 Hz vs 91 Hz）——
IMU 回调被 NDT 挤掉了。

修法：点云超过 `ndt.max_cloud_age_s`（150 ms）直接丢。实测一整场只丢 1 帧，
就避免了整个级联 —— 最坏退化成「NDT 更新少了」，由 GNSS 兜住。

> **教训**：我一度把耗时判据当成"无关痛痒的尾部问题"，那个判断是错的。
> 在一个单线程回调里，**算得慢不是精度问题，是正确性问题**。

#### (3) 均匀降采样扔错了点

地面点冗余度极高，而杆件本来就只有几个点（半径 0.15 m，20 m 处每线才 4.3 个）。
按同一比例扔，扔掉的恰好是**唯一提供 x/y/yaw 约束**的那些。

实测：均匀 stride 从 4 改到 8，耗时 129→78 ms，但横向误差 **0.0664→1.72 m**，
日志里冒出「NDT 退化（法向散布 0.000743）」。

修法：**按类别降采样** —— 结构点 stride 4、地面点 stride 24。
总点数降下来了、信息量一点没少：耗时 129→35 ms 而精度不降。

⚠️ 地面点**不能全扔**：退化判据看的是匹配体素的法向散布，全扔之后只剩水平法向，
竖直方向的 λ_min → 0，NDT 会被**自己的退化判据**误杀。

#### (4) GNSS 杆臂

天线装在 `(0.5, 0, 1.6)`（`vehicle_params.yaml` 的 `sensors.gnss`），
而 ESKF 把 GNSS 报的位置当成了 `base_link` 的位置。偏差是**系统性**的：

* 竖直 1.6 m 常量 —— 会把 NDT 的初值顶出收敛域
* 水平 0.5 m —— **随车头方向旋转**，看起来像「定位在某些朝向上偏得多」

它不会让滤波器发散，只会让它稳定地偏一点 —— 于是所有人去调 `Q`，
而错在一次坐标变换里。

铁证：连续两轮的初始 z 都是 **1.58 / 1.59**，与天线高度 1.6 严丝合缝。

修法：`p_base = p_天线 − R · r_天线`，杆臂从 YAML 经 launch 传入。

#### (5) 开机第一帧锁错 —— 而「连续 N 帧被拒」抓不到它

**锁错的定义就是「NDT 报告成功」**，所以它不会连续失败。
实测：55 帧被拒但**从未连续 3 帧**，恢复机制一次都没触发，而定位错了 28 m。

最脆弱的时刻是开机第一帧：初值只有 GNSS 均值（σ=0.37 m，2σ 就是 0.74 m），
而精配准的收敛域只有约 **0.3 m** —— 受 σ_n = 0.058 m 的薄高斯限制
（2 m 体素 × 特征值下限 0.01）。一旦第一帧锁错，之后每帧都从那个错位姿附近
重新收敛，再也回不来。

修法：开机头 5 帧**无条件**走粗→精。粗网格要同时放大**两个**量才有用：

```
体素 6 m  且  特征值下限 0.05   →   σ_n ≈ 0.39 m，收敛域约 1 m
```

**只放大体素而不放宽下限，高斯还是同样地薄，白搭。**

L1 用例 `NdtAlign.CoarseGridRecoversFromOutsideTheFineConvergenceBasin` 守着它
（不需要仿真器）：初值偏 1.80 m 时，只用精网格 → 1.597 m **且被判退化**；
粗→精 → **0.002 m**。

### 10.3 四档降级状态机

`INITIALIZING` → `NDT_AIDED` → `GNSS_ONLY` → `DEAD_RECKONING`，发在 diagnostics 里。

**「位置还行」和「位置还行但已经退化成纯推算」在数值上一模一样** ——
只有把状态发出来才分得开。

⚠️ NDT 报 `degenerate` 的帧**不喂给滤波器**。退化意味着代价函数沿某些方向是平的，
那几个方向上的位姿是任意的。

⚠️ 但**不要顺手加上 `|| !converged`** —— 试过，结果更差（横向误差 0.0664 → 1.99 m，
899 拍掉进 `GNSS_ONLY`）。车动起来时很多帧到迭代上限才停，位姿其实已经很好；
`converged` 只说「步长小于 epsilon 了吗」，不说「位姿好不好」。

### 10.4 CP-P4-B 实测汇总（2026-08-10，连跑两轮）

| 判据 | 第 1 轮 | 第 2 轮 | 上限 |
|---|---|---|---|
| 定位横向误差 | **0.1291** | **0.0869** | 0.30 m |
| 航向误差 | 0.4554° | 0.6807° | 2.0° |
| 累积漂移 | 0.0402 | 0.0615 | 0.50 m |
| NDT 单帧耗时 | 37.5 ms | 44.3 ms | 100 ms |
| CP-P2-B（**估计位姿下**） | **8/8** | **8/8** | — |
| RMS 横向误差（参考） | 0.0327 | 0.0205 | — |

CP-P3-B 在估计位姿下：绕 **5/5**（最小侧向间距 0.555 m）、停 **4/4**（停车间距 1.059 m）。
两轮 **NDT 一帧都没被拒**。

### 10.5 ⚠️ 两条量测上的陷阱

**(a) 单次通过不算数。** 中途有一轮拿到「横向 0.0664 m、CP-P2-B 8/8」，
下一轮同一份配置得到 **78 m**。判据必须**连跑至少两轮**，
`cp_p4b_x2.sh` 把这条固化下来了。

**(b) `record_control_run.py` 在 `localization:=true` 下量的是「估计位姿相对路径」。**
定位整体偏移时，控制会把车开到让**估计**贴合路径的地方 —— 看起来完美而车实际偏了。
实测有一轮「定位错 3.24 m 而 CP-P2-B 8/8」。
**CP-P4-B 第 6 条判据单独不成立，必须配定位判据一起看。**

### 10.6 L3-G：不需要 GPU 的定位闭环（S5）

`src/ads_localization/test/test_closed_loop_localization.py` + `fake_sensors_node.cpp`。
`colcon test` 会跑，所以 CI 也跟着跑 —— 与 `ads_control` 的 L3-G 是同一层的两个用例。

假传感器从**先验点云 `campus_cloud.pcd` 里抠扫描**，也就是「世界」与「地图」同源：

实测末段平均位置误差 **0.012 m** —— 这个数好看，但它不是定位质量的证据，
判据定在 0.60 m（是"没发散"，不是精度考核）。**收紧到 CP-P4-B 的 0.30 m
得到的不是更强的保证，而是一个在 CI 上随机变红的测试。**

五条断言：① 末态必须是 `NDT_AIDED`（不是"出现过"——出现过又掉回 `GNSS_ONLY`
正是 S4 那次失锁的形态）；② 陈旧点云一帧不许丢；③ `/tf_static` 上不许有
`map→odom`；④ `map→odom` 必须约等于自车起点；⑤ 末段误差不发散。

**故障注入实测**（写完立刻做的，四条见测试文件头的表）。两条「抓不到」的比抓到的重要：

- **多一个 `map→odom` 发布者，数值上看不出来** —— 误差只从 0.012 变成 0.043 m。
  所以断言 ③ 是机械地查 `/tf_static`，不是看误差。理由见 §10.1。
- **这一层看不见杆臂补偿** —— 节点侧杆臂清零后误差 0.012 → 0.018 m。
  NDT 一锁上，GNSS（σ=2 m）在融合里几乎没有权重，0.5 m 的杆臂偏差被压进了噪声。
  **杆臂归 CP-P4-B 验**，那里 GNSS 是唯一的绝对基准。

⚠️ 加它的时候踩到一个跨包的坑：colcon 是**按包并行**跑测试的，
`ads_control` 与 `ads_localization` 的闭环于是同时在跑，默认 `ROS_DOMAIN_ID=0`
